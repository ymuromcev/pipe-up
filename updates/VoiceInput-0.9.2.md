
### Added

- What you say to Claude while it works reaches it right away, as when you type in Terminal during a turn. It used to wait for the whole turn to end. The message shows dimmed at the end of the conversation, "Claude will read it after the current step"; once Claude reads it, it moves into the conversation where Claude read it, and Claude's next words come under it — the same turn, one answer at the end. If Claude Code is still starting, the message waits with "Waiting for Claude Code to start" and goes as soon as it's up.
- "Waiting:" in the bubble lists everything you said that Claude hasn't read yet, in the order you said it, each with why it waits, and each with × to take it back: Claude won't get it. If Claude read it in the same instant, it stays in the conversation marked "Claude has already read it". The list replaces "Queued:", which showed commands without a way to remove them.
- When Claude's usage limit runs out, the bubble says so calmly — "Claude's usage limit is used up. It's back at 2:00 PM. What you say until then waits and goes by itself." — instead of a red "Claude Code: something went wrong" with an English error line. With the bubble closed, a notification says the same. The time is by your Mac's clock: "at 2:00 PM", "tomorrow at 9:00 AM", "on Friday at 9:00 AM". What you say meanwhile isn't sent into an error: it waits under "Waiting:" ("Goes at 2:00 PM, when the limit is back") and goes by itself, in order, when the limit is back, even if the Mac slept through that moment. The interrupted task doesn't continue by itself: say "continue", and that waits too. If what went by itself hits the limit again, it waits for the next time; after two such times in a row, or if Claude Code doesn't say when the limit is back, the messages wait for Send.
- A permission request names the sites a command wants to reach: "Run command: npm install · Network: registry.npmjs.org, *.npmjs.org" (Claude Code 2.1.271 or later, auto mode, sandbox on). Allow allows the command and those sites, for that command only. When the sandbox asks about a single site — "Network access: github.com" — Deny closes just that site and Claude carries on; there's no field for instructions, since Claude Code doesn't pass them on, and a spoken "yes" allows it while anything else denies it. When auto mode keeps a command off the network without asking, a quiet line in the conversation names the sites.
- "Stop" in the bubble. While Claude works, the button at the bottom right says "Stop" instead of "Open in Terminal". It ends Claude's turn the way Esc does in Terminal: a running command is cut off, an open question or permission request closes, and the bubble says "Stopped. Claude is waiting for your next command." The conversation stays: your next command continues it. Anything you said that Claude hadn't read yet doesn't go by itself: it waits under "Waiting:" marked "Stopped — not sent", with Send and ×. Skip on Claude's question and a plain Deny, which stop Claude too, hold such messages the same way instead of starting a new turn with them. If Claude Code doesn't stop within 10 seconds, Pipe Up closes it, and the next command continues the same conversation.
- Your Mac doesn't fall asleep while Claude Code is working on a task you gave it. Once the task is done, the Mac sleeps as usual. While Claude waits for your answer to its question or permission request, the Mac may sleep; once you answer and Claude works on, it stays awake again. The screen still turns off on its own schedule, and closing a laptop's lid still puts it to sleep.

### Changed

- Claude Code 2.1.270 or later is needed. An older one gets the usual "Update Claude Code" with its Update button.
- Dictation works almost right away in every language macOS's own speech engine knows, not just in English. Until the speech model is ready, macOS does the listening. If your Mac doesn't have that language's speech files yet, they download in the background next to the model, and whichever is ready first starts answering. Russian and other languages macOS doesn't know start once the model has downloaded, as before.

### Fixed

- A dictation is no longer lost when the Mac's microphone hands over a moment of sound far louder than the scale allows. It happened on 20.09.2026: macOS delivered ten seconds of one take at about nineteen times full scale, the speech model answered with nothing at all — twice — and 12.7 seconds of a 28-second dictation never became words. Such moments are now levelled off before the take reaches the model, and everything spoken around them arrives exactly as it was said.
- A dictation that came back with no words at all no longer disappears without a word. When you spoke and not one word came back, the pill now says "Nothing was recognized" and stays a moment, so you see it happened and can say it again; before, the pill simply went and the only notice was a line in the menu, which is closed while you dictate.
- A dictation you cancel with Esc no longer leaves a "Canceled" line in the menu: the pill going away is the whole answer.

- A one- or two-word answer — a city, a colour, a name — now comes back as words. Anything you said in under a second never reached the speech model at all: the pill said "Couldn't make anything out", and an answer to Claude's question was never sent. Ordinary dictation runs longer and was never affected, which is why this only ever showed up on quick answers.
- With two copies of the app installed, the one waiting for the other's model download now shows how far that download has got instead of sitting on "Downloading: 0%" until it finishes.
- A short take is no longer counted as holding no speech at all. A word or two with no pause in them used to set the app's own "this is speech" bar above the whole recording, so nothing in it could be reported as lost and a piece the vocabulary spoiled was never read a second time.
- The bubble's header no longer shows an internal folder name. A conversation in a folder you set by hand gets a worktree called `pipe-up-<date>-<time>` — in your repository's worktree list too — and conversations started before this keep working, just without a name in the header.
- In Russian, "Открыть системные настройки" on the Permissions tab no longer wraps onto two lines and pushes its row taller than the others.
- The label beside a switched-off checkbox in Settings is readable in both themes.
- In Russian the speech model is downloaded in one word throughout — «скачать». Settings used to call one thing «Загрузить», «Качаю» and «скачиваю заново», while «Загружаю модель…» meant something else: the model coming up into memory.
- The Russian wizard no longer breaks «что-нибудь» across two lines.
- Quitting in Settings is «Завершить приложение» in Russian, the word macOS uses; «Закрыть» is about a window.
- The pill names the clipboard the same way in both of its lines: "On the clipboard" next to what wasn't recognized, instead of "Copied".
- A step forward in the bubble's questions is "Continue", the word the wizard uses, instead of "Next". In Russian both were «Дальше» already.
- A speech model download that was cut short (sleep, shutdown, a dropped connection) or left files missing is no longer taken for a finished one. The app checks the model's files before using it and downloads whatever is missing by itself. A model that still won't open is downloaded again, and Settings says "The recognition model is damaged — downloading it again" instead of a technical error with a file path in it.
- Switching the dictation language while the speech model was downloading could leave the model without its largest file.
- A permission request for a tool Pipe Up doesn't know — an MCP tool that sends email, for example — shows everything the tool will get, lists of recipients and nested details included, text in quotes so one field can't pass for another. Before, only its first few text fields were shown, while Allow approved the rest too. If it's too long to show whole, the request says how many more fields there are and names them.
- Changing the dictation language, or switching back to the model that's downloading, in the first seconds of the download no longer leaves the model "not downloaded" until a restart: it starts as soon as the download is done. The model is also no longer loaded twice over when the language changes mid-download.
- macOS's own dictation no longer starts on a double ⌃ while Pipe Up is running, whatever your dictation key is. While the macOS dictation shortcut is "Press Control Key Twice", Pipe Up hides the second quick ⌃ tap from it, as it already did when ⌃ was its own key. Single presses, ⌃-click and ⌃C work as before. Other macOS shortcuts (off, 🌐, ⌘ twice) are left alone.
- A dictation key set to right ⌥ alone stays right ⌥ after the app restarts. It used to come back as right ⌥ or ⌃.
- The right ⌥ and the right ⌃ are now set as a pair: press either one while choosing a key, and the dictation key becomes "Right ⌥ or ⌃" — both of them. Neither can be set on its own any more, because keyboards differ about which of the two they have. The key list offers the pair instead of the two single keys. Every other key is set exactly as pressed, ⌘ is still refused, and a single right ⌥ or ⌃ set by an earlier version goes on working until you pick a key again.
- When Pipe Up finds an update by itself, the update window comes to the front. It used to open behind other windows, where it was easy to miss.
